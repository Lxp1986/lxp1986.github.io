新圩那个水毁修复的渠道清淤量，我原来是在 Excel 里做的，一条渠一块，公式写 `=(C3-1*D3)*D3*B3`。现场复量回来淤厚从 0.5 改成 0.6，我改完数值还得挨个格子点进去看公式有没有拖对；更要命的是给别人复核的时候，人家问「这个 3211.87 哪来的」，我得先把 C3、D3 翻译成上口宽、淤厚，说半天。

后来把这套表挪进了 FreeCAD 的电子表格（Spreadsheet 工作台）。理由很简单：单元格可以起别名，公式里写的是名字，不是列号。

要是你一年只改两次、就十几行，Excel 的名称管理器也够用，不用折腾。我这边的量是有几十条渠、断面形式分土渠和溪河两套、边坡系数还不一样，改一处的次数太多，才值得把它固定成一张能读能核对的表。

![FreeCAD 电子表格：参数格起别名，公式格写名字](/img/fc-sheet-alias.svg)

## 建表：参数区和结果区分开

FreeCAD 打开，新建文档，顶上工作台下拉切到 **Spreadsheet**，工具栏点「新建电子表格」。存成 .FCStd。

表这么排（跟 Excel 没区别）：

| 单元格 | 内容 | 别名 |
|---|---|---|
| A2 / B2 | 渠长 120 | `len` |
| A3 / B3 | 上口宽 3.5 | `Btop` |
| A4 / B4 | 淤厚 0.5 | `thick` |
| A5 / B5 | 边坡系数 1 | `mval` |
| A6 / B6 | 清淤量（公式） | `vol` |

数字格一律填纯数字，`120` 就写 `120`。**别写 `3.5 m`** —— 我试过，带单位的数 FreeCAD 内部按毫米存，单元格里看着是 3.5 m，`=B3*2` 算出来是 7000 mm，不是 7。单位单独放 C 列当文字（写 `m`、`m3`），表格导出时照样带出去。

别名怎么起：右键单元格 → **Properties（属性）** → 在 Alias 那一栏填名字。

这一步有两个实测会卡人的地方：

- **别名别用单字母单位符号**。`L` 能过，`H`、`M`、`V`、`J`、`W` 直接报 `Invalid alias`，FreeCAD 拿它去和单位符号比对了。写成 `thick`、`vol`、`Btop` 这种词就没问题。
- **空格子起别名也报错**（`Invalid cell address or property`）。先填数，再设别名。

## 公式：写成名字，函数名必须小写

双击单元格输入，表达式必须以 `=` 开头：

```
=(Btop-mval*thick)*thick*len
```

这就是梯形断面清淤量的算法——上口宽减掉边坡乘淤厚，得到底宽，再乘淤厚乘渠长。表里看到的是这四个参数名，不是四个列号，谁复核都能顺着念出来。

三个我实际撞过的地方：

- **函数名一律小写。** 合计我一开始写 `=SUM(F2:F3)`，FreeCAD 1.1.3 上不报错、也不算，单元格里就干留着那串文字，读出来还是字符串。改成 `=sum(F2:F3)` 才对。判断表达式到底算没算成功，看返回值：如果读出来是以 `=` 开头的字符串，就是没算。
- **`round()` 只吃一个参数。** `=round(x; 2)` 会报 `Invalid number of arguments: exactly one required`。要四舍五入到两位，写 `=round(x*100)/100`。
- **表里改完数要重算。** 图形界面里自动，脚本里得自己调 `doc.recompute()`，不调就是旧值。

## 导出给报价用

表格上右键 → **导出电子表格**（Spreadsheet 工作台菜单里也有 Export Spreadsheet）。反过来也支持「导入电子表格」把 CSV 参数直接灌进来。

导出的这个 `.csv` 要多说一句：它其实是**制表符分隔、UTF-8 无 BOM** 的纯文本（我用 `xxd` 看过，文件开头就是「项」的三个字节，没有 BOM）。Excel 双击打开会把整行挤在一格里，导入时把分隔符选成**制表符**；OnlyOffice 打开时同样会问分隔符，选制表符就正常出表。

## 几十条渠，一个脚本算完

图形界面适合调一张表。真到几十条渠，我直接走命令行——macOS 上 FreeCAD 自带的 `freecadcmd`，不用装任何东西。

先准备参数表 `qd.csv`（逗号分隔，UTF-8）：

```
渠别,长m,上口宽m,淤厚m,边坡m
土渠A,120,3.5,0.5,1
溪河B,86,4.2,0.6,1.25
```

脚本 `算量.py`：

```python
# -*- coding: utf-8 -*-
import FreeCAD as App, csv

doc = App.newDocument("batch")
s = doc.addObject("Spreadsheet::Sheet", "计算表")
for c, h in zip("ABCDEF", ["渠别", "长m", "上口宽m", "淤厚m", "边坡m", "清淤量m3"]):
    s.set("%s1" % c, h)

r = 2
with open("qd.csv", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        for c, k in zip("ABCDE", ["渠别", "长m", "上口宽m", "淤厚m", "边坡m"]):
            s.set("%s%d" % (c, r), row[k])
        # 梯形断面清淤量，round 只收一个参数，所以先乘 100 再除回来
        s.set("F%d" % r, "=round((C{0}-E{0}*D{0})*D{0}*B{0}*100)/100".format(r))
        r += 1

s.set("A%d" % r, "合计")
s.set("F%d" % r, "=sum(F2:F{0})".format(r - 1))
doc.recompute()          # 不调这一步，导出的还是空值
s.exportFile("清淤量.csv")
print("共 %d 条渠" % (r - 2))
```

跑：

```bash
/Applications/FreeCAD.app/Contents/Resources/bin/freecadcmd 算量.py
```

上面这两条渠跑出来的结果：土渠A 180、溪河B 178.02、合计 358.02，导出文件直接就是报价书里能用的表。

脚本里有个细节值得先知道：`s.get()` 去读一个空单元格会抛 `ValueError: Invalid cell address or property`，跟表达式写错报的错很像，容易认错方向。读之前判一下，或者干脆别读空格。

## 表里的数还能给模型绑尺寸

这条我偶尔用：选中模型对象，属性栏里 Length 右边的 **fx** 图标点开，填 `参数.len`（对象名加别名），改表里的数模型跟着变，体积面积也能反过来读进单元格。

算量本身用不上——我算的是现场量回来的渠道，不是画出来的盒子。但验断面画得对不对的时候挺省事，改个数就知道模型尺寸吃进去了没有。

最后说句实话：这表只保证「算得一致」，不保证你填进去的上口宽是现场量回来的那个数。该核的断面还得核。它的好处是复核的时候公式摊开就能读，不用再翻译列号。
